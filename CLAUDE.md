# CobbVision iOS — agent notes

- **Never commit an `.xcodeproj`** — the project is generated by XcodeGen from
  `project.yml`. Targets, entitlements, Info.plist keys, and SPM products all
  live in that file.
- **All logic goes in `Packages/CobbVisionKit`**, not in `App/`. The app target
  is a thin SwiftUI shell. New code needs a home in one of the CV* modules.
- **`CVCore` must stay platform-pure** (Foundation only, no Apple-only
  frameworks) so it compiles on Windows/Linux. iOS-only modules wrap their
  entire file contents in `#if os(iOS)` so `swift test` works on macOS hosts.
- Concurrency: Swift strict concurrency is `complete`. Services are actors or
  Sendable protocols; AVFoundation/CoreBluetooth delegates are bridged to
  AsyncStreams at module boundaries.
- There is no Mac in the loop: verification happens on GitHub Actions
  (`ci.yml`). Device-only features (camera, motion, BLE) are tested via
  TestFlight builds; keep their logic behind protocol seams with fakes
  (`FakeCaptureEngine`, `ReplayMotionSource`, `FakeCameraController`) so the
  state machines stay unit-testable.
- Controlplane API reference lives in the sibling repo
  `C:\Users\grio\Documents\Code\CobbVision` (`docs/openapi.yaml`,
  `src/routes.php`). Auth is `Authorization: Bearer <api_key>`.
- Backend changes for this app are specced in `docs/backend-additions.md` and
  implemented in the CobbVision PHP repo, not here.
